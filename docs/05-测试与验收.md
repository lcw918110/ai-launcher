# AI 终端启动器 — 测试与验收

分两层：**Core 纯逻辑测试（可进 CI，无副作用）** + **GUI 冒烟/手工验收**。

## 1. 目录

| 文件 | 职责 |
|------|------|
| `src/Core.swift` | 纯逻辑层（仅 Foundation）：连接串解析、路径/主机拆分、shell 转义、命令拼装、配置读写、`~/.ssh/config` 解析、启动脚本生成 |
| `src/main.swift` | 入口（AppKit）：`NSApplication` 启动 + `--selftest` 开关 |
| `src/AppShell.swift` | 无状态 UI 辅助：写临时 `.command`、`open` Terminal、旧文件清理、目录选择 |
| `src/AppDelegate.swift` | 窗口、滚动视图、菜单（含「工具」）、生命周期、`--selftest` 冒烟 |
| `src/CopyForm.swift` | 互拷表单：控件构建、免密联想、远端浏览、表单快照（`extension AppDelegate`） |
| `src/CopyRunner.swift` | 互拷执行：参数校验、直连探测选路、启动 Terminal、轮询日志回收结果 |
| `src/SuggestionController.swift` | 免密主机候选框（`NSPopover` + `NSTableView`） |
| `tests/main.swift` | Core 全量断言用例（纯命令行） |

### 文档一致性校验

```bash
./scripts/check-docs.sh                 # 自己跑测试取实际条数
./scripts/check-docs.sh --assert-count 453   # CI 里复用上一步的结果，不重复跑
```

断言只保证代码对，保证不了「文档写的是不是当前代码」。2026-11-02 工作区的 docs/、README、`build.sh` 被整批回退到 10-29 的版本（净少 490 行，断言数还停在 124），没有任何机制报警，靠人工翻文档才发现。这个脚本就是补这个口子，它查五件事：

| 检查 | 失败含义 |
|------|----------|
| `Info.plist` 版本 == `CHANGELOG` 最新条目标题 | 发版时只改了一处 |
| `docs/05` 的「覆盖范围（N 条断言）」== 实测通过数 | **文档落后于代码**（回退事故的典型症状） |
| 除该处外，其余 md 不再硬写当前断言数 | 又制造了一份副本，早晚不一致 |
| 文档里「（当前 x.y.z）」== `Info.plist` | 版本号散落在说明里 |
| 现行规格/使用说明不含已下线功能的旧句式 | 代码删了功能，文档还在教用户点它（2026-11-12 查到 docs/02 还写着「经本机中转」按钮） |

历史记录（`CHANGELOG`、各文档的修订记录表）不参与校验，那些数字本来就该是旧的。CI 的 `build-and-test` 与发版流程都会跑它，不一致直接失败。

### 界面控件接线检查

```bash
./scripts/check-ui-wiring.sh     # test.sh 末尾与 CI 各跑一遍
```

界面上的**输入控件必须有「值被生产路径读取」的证据**。只创建、只回显、只在表单快照里搬运、只在自测里断言「存在」，统统判失败。检查器还自带**自检**：喂一份只有创建/回显的假控件代码，必须识别成孤儿，否则检查器自己报错——避免「检查器假绿」重演 0.5.0 的教训。

第二项「启动脚本收尾」检查脚本产物契约：`launchInTerminal` 必须走 `buildToolLaunchLine`，不得再用 `exec <CLI>` 顶替 shell，收尾须用分号并 exec 到交互 shell。同样喂两份假代码自检（旧 exec 写法、缺交互 shell 的收尾都必须报错）。

| 控件 | 值流向（消费点） |
|------|------------------|
| `toolPopup` | `otherDirLaunch` 取 `selectedItem` 里的命令 |
| `copySourceField` / `copyTargetField` | `makeCopyParams` 拼 `CopyParams`；`resolveParseTarget` 决定解析回填哪个框 |
| `copyConnField` | `parseConn` 解析；`startCopy` 用 `needsParseReminder` 判断是否未解析 |
| `copyUserField` / `copyHostField` / `copyPortField` | 只读展示，但仍被读：`makeCopyParams` 给相对路径补 host 前缀、`browseHostPlan` 供「浏览远端」兜底 |
| `copyPreserveCheck` / `copyResumeCheck` | **默认折叠在「高级选项」区**（值仍接线）：`makeCopyParams` → `CopyParams` → 命令参数，并参与 `resolveDirectRoute` 选路；`toggleAdvancedOptions` 读状态生成 tooltip 摘要 |
| `copyBwlimitField` | 同上折叠；`parseBwlimitMBps` → `--bwlimit` / `scp -l`；`advancedSummary` 生成 tooltip |

新增控件先在这张表补一行，再确认检查通过。纯输出控件（`copyStatusLabel`）与探测期按钮（`copyStartBtn`）不参与检查。

## 4. GUI 冒烟 `--selftest`（可选）

```bash
/tmp/ai-launcher-check --selftest
```

会真正启动窗口，1 秒后模拟点击第一个启动按钮（可能弹出 Terminal 跑配置里的第一个 CLI），检查内容在滚动视图内、窗口可缩放、PATH 前缀，并跑 6 条「解析连接串 → 回填路径」的 GUI 冒烟（日志 `解析回填 6/6 PASS`）、5 条界面接线契约（`界面接线 5/5 PASS`）与 9 条人工反馈契约（`人工反馈四连 9/9 PASS`：焦点切换连点两次解析、密码去向与不落明文、无效路径点浏览远端、4 条脏输入矩阵、目标框浏览按钮、高级选项默认折叠 / 展开 / 收起、按钮覆盖契约）。**不再断言「控件存在」**——控件被创建不等于它接上了行为，那正是 0.5.0 假绿的来源。这些都**模拟真人操作**：只走 `firstResponder` 切换、系统通知与按钮 `performClick`，不手动塞状态变量、不直接调 `parseConn`。点击后还会读**真正写到磁盘的那份 `.command`**，断言 CLI 退出后能回到交互 shell（日志 `启动脚本收尾 = PASS`）；`--no-launch` 时明确记 `SKIP`，绝不算 PASS。约 5 秒后自动退出。日志 `/tmp/ai-launcher-debug.log`。

加 `--no-launch` 可跳过「点第一个启动按钮」，只做窗口/控件检查，不会弹 Terminal：

```bash
/tmp/ai-launcher-check --selftest --no-launch
```

纯逻辑断言已全部迁到 `tests/main.swift`，`--selftest` 不再承载回归职责，只做界面链路冒烟。**不带 `--no-launch` 时不要在无人值守环境跑**（会弹 Terminal）。

### 脏输入矩阵与按钮覆盖契约（0.5.4）

「这么明显的 bug 为什么还要人工发现」的答案是：过去 GUI 自测只跑 happy path，且只断言控件存在。现在两层硬约束：

1. **按钮覆盖契约**：自测里所有真人点击统一走 `click(_:)` 记账，末尾遍历互拷区所有**动作按钮**（`action != nil`，排除会弹文件面板的「选择…」；复选框由接线检查覆盖），要求每个都至少有一条用例。`解析`、`浏览远端`、`开始拷贝`、`高级选项` 缺一个即报 `按钮覆盖契约 = FAIL`；界面上新加按钮却没写用例也会红。
2. **脏输入矩阵**：`abc`、`ssh://bad`、`乱码:xxx`、`notahost:/tmp`、误填的本地路径等，逐条真人点击「浏览远端」，断言在弹窗 / 发起 ssh 之前被拦下且状态栏有可读提示。这些输入在修复前会弹 `NSAlert` 卡住自测或真的连一台假主机——正是用户人工撞见的那种「打开报错」。

配合 Core 的 `browseHostPlan` 差分断言（带端口路径保留端口、起始路径不被端口污染）与 `zsh -n` 脚本语法校验，把「值被读了却没生效」「输入脏了才崩」两类问题挡在交付前。

再验「结果回写状态栏」这一跳（需要 Terminal 真跑一次拷贝）时加 `--selftest-copy`，它用 `last-copy.json` 的源/目标启动拷贝，14 秒后把状态栏内容写进调试日志：

```bash
"/Users/xxx/Applications/AI终端启动器.app/Contents/MacOS/AI终端启动器" --selftest --no-launch --selftest-copy
grep "状态栏 =" /tmp/ai-launcher-debug.log   # 期望：✅ 拷贝完成（退出码 0）
```

注意：从**沙箱里**（如自动化工具）拉起这个进程时，`open` 会因为沙箱禁止「把文稿交给别的 app」而什么都不做（退出码仍是 0，`NSWorkspace` 的 completionHandler 也只回报 `error=nil`）。这时状态栏如实停在「已交给 Terminal，等待脚本开始」——这正好可以当「脚本没起来」这一档的现成验证场景，不用额外造。

## 5. 手工验收（P0）

| 项 | 操作 | 期望 |
|----|------|------|
| 网格启动 | 点某个目录的 opencode | Terminal 工作目录为该路径 |
| 刷新 | 改 `dirs` 后点刷新 | 行数与名称变化，且互拷表单已填内容不丢 |
| 滚动 | 把窗口拖矮 | 出现竖向滚动条，底部「开始拷贝」可滚动到 |
| 本机→远端 | 小文件 push | 远端出现文件，成功关窗（且只关本 tab 窗口） |
| 解析（焦点） | 点一下源路径框（可先「选择…」选个本地目录），再在连接串粘贴 `user@host` 点解析 | 用户名/主机回填，**源路径**变成 `user@host:/原路径`；焦点保持原位，程序不抢光标 |
| 解析（换焦点） | 接着点一下目标路径框，再点一次解析 | 这次补到目标；源不再被改写（`人工反馈四连` G 用例覆盖） |
| 解析（端口） | 粘贴 `192.168.1.5:2222` 点解析 | 主机框 `192.168.1.5`、端口框 `2222`，用户名框为空 |
| 解析（没点过路径框） | 启动后不碰路径框，让 `last-copy.json` 回填源路径，直接粘连接串点解析 | **必须填入且不覆盖已填框**：源路径原样保留，空的目标框补成 `user@host:`；状态栏写明填了哪个框 |
| 解析（两框都空） | 两个路径框都空，粘连接串点解析 | 目标路径得到 `user@host:` 这个可续写起点（默认本地推远端），状态栏说明怎么换 |
| 解析（两框都有内容） | 源、目标都填了本地路径，没点过任何框 | 填目标（确定规则）；想改就把焦点放进源框再解析 |
| 解析（带密码） | 粘贴 `user:pass@host` 点解析 | 凭据行只有用户/主机/端口；状态栏明说密码不保存、在 Terminal 输入；任何回填框都没有明文 |
| 解析（焦点优先） | 点过目标框，但源框也有内容 | 只填目标，不串到源 |
| 解析（重复） | 对同一路径框再点一次解析 | 只换 host 前缀，不叠加成 `host:host:/path` |

## 真实链路验证（无内网时也能做）

断言只验证「命令字符串长什么样」，验证不了「命令跑起来结果对不对」。2026-10-30 用下面这套方法真跑了一遍，才暴露出中转落点的两个 bug。手边没有可连的内网机器时，用本机 Docker 起一个临时 sshd 即可：

1. 本地镜像（Ubuntu）里装 `openssh-server` + `rsync`，把本机公钥放进 `/root/.ssh/authorized_keys`，`CMD sshd -D`
2. `docker run -d -p 2222:22` 起来，`ssh -p 2222 root@127.0.0.1` 能免密登录
3. 用一个包装脚本让「app 生成的命令」里的 `ssh` 读到临时配置：`PATH=/tmp/relay-bin:$PATH`，脚本内容为 `exec /usr/bin/ssh -F <临时 config> "$@"`（`HOME` 覆盖无效，OpenSSH 走 `getpwuid`）
4. 写个 10 行小程序链接 `src/Core.swift`，直接打印 `buildRelayCopyCommand` / `buildRelayResumeCommand` 的结果 —— 验证的就是线上那条命令，不手抄
5. 执行后 `find` 目标目录看层级、`md5sum` 比内容；续传场景用大文件跑 2 秒后 `pkill -f "rsync"`，再看 `.rsync-partial` 里的半截文件与重跑行为
6. 验证完 `docker rm -f` / `docker rmi`、删掉临时目录，并清 `~/Library/Caches/ai-launcher/relay` 里的测试残留

### 2026-10-30 直连续传实测（Docker + openssh + rsync 3.4.3）

200 MB 随机文件，限速 `--bwlimit=2000`（2 MB/s），6 秒后对 `rsync` 进程发 `SIGINT`：

| 观察项 | 旧参数 `--partial --append-verify` | 新参数 `--partial --partial-dir=.rsync-partial` |
|--------|-----------------------------------|--------------------------------------------------|
| 目标最终路径 | 出现 11.6 MB 的 `big.bin`（残缺，易被误判为传完） | 不出现文件 |
| 中断现场 | 直接落在最终文件名上 | `.rsync-partial/big.bin` 11.8 MB |
| 重跑 | 从头传（目标缺尾，追加无效） | `Matched data 11,826,672` / `Literal data 197,888,528`，只补剩余 |
| 完成后 | — | md5 与源一致，`.rsync-partial` 自动清空 |

复现要点：中断信号要打到 `rsync` 进程本身（`pkill -INT -f '<源路径>'`），只杀外层 subshell 的话 `rsync` 会继续跑完，看不到断点现场。

### 2026-10-30 限速与日志实测（Docker + openssh + rsync 3.4.3）

60 MB 随机文件，用 app 拼出的命令（`--bwlimit=2048 --log-file=…`）推远端，6 秒后打断：

| 观察项 | 结果 |
|--------|------|
| 限速是否生效 | `sent 12503969 bytes` / 6 秒 ≈ 2.08 MB/s，与 2 MB/s 设定一致（同一文件不限速时本地回环 1 秒内完成） |
| 中断现场 | `.rsync-partial/data.bin` 12.48 MB，最终路径无文件 |
| rsync 日志 | 有 `building file list`、`sent 12503969 bytes`、`rsync error: received SIGINT … (code 20)` |
| 重跑 | `sent 50459070 bytes`（只补剩余），md5 与源一致，`.rsync-partial` 自动清空；日志追加第二段，共 6 行 |
| 脚本层日志 | 成功：`[时间] 开始 …` / `[时间] 结束，退出码 0`；失败（`(exit 23)`）：记 `退出码 23` 并把 23 透出 |

两个坑：`--log-file` 的目录必须已存在（应用脚本里先 `mkdir -p`，手工验证时要自己建）；命令里若直接写 `exit N` 会跳过脚本末尾的日志收尾，真实拷贝命令是 rsync/tar 链不会这样，验证失败路径请用 `(exit N)` 子 shell。

### 2026-11-03 真实内网双机实测（两台 Linux，rsync 3.2.7 / GNU tar 1.34）

前面几轮用的是本机 Docker 单容器，跨机链路（源机 → 目标机）一直没真跑过。这次拿两台内网机（记为 A、B）补上，命令仍由 `buildCopyCommand` / `buildRelayCopyCommand` / `buildRelayResumeCommand` 现算，不手抄。数据 40 MB 随机文件，两端均为 `/tmp` 下临时目录，测完删除。

| 场景 | 结果 |
|------|------|
| 本机 → A 推送（限速 3 MB/s、带 `--log-file`） | 40 MB / 14 秒 = 2.94 MB/s；落点 `A:/tmp/la-t/data/data.bin`；md5 一致；日志 3 行（`building file list` / `<f+++++++++ data.bin>` / `sent 41953385 bytes`） |
| A → 本机 拉取 | 86 MB/s，落点本机 `pull/data.bin`，md5 一致 |
| 推送中断（限速 1 MB/s，SIGINT） | 半截 5,144,576 字节在 `A:…/data/.rsync-partial/data.bin`，**最终路径无文件** |
| 同任务重跑 | `Matched data: 5,143,808` / `Literal data: 36,799,232`，md5 一致，`.rsync-partial` 自动清空 |
| 断网模拟（`kill -9` 打 rsync） | 半截 6,193,152 字节保留在 `.rsync-partial`；重跑 `Matched 6,192,632` / `Literal 35,750,408`，md5 一致 |
| A → B 直拷（A→B 无免密） | 失败，B 上无文件；在真实 tty 里能看到 `<user>@B's password:` 提示，说明 `ssh -t` 的密码交互可用，只是要人工输一次 |
| A → B 中转 tar 流 | 1 秒完成；落点 `B:/tmp/la-t2/data/data.bin`（不多嵌一层）；md5 一致；重复执行不套娃 |
| A → B 中转可续传 | 落点同上；中断后暂存 `~/Library/Caches/…/data-<哈希>/data/.rsync-partial/data.bin` 保留 4,882,432 字节，B 上无文件；重跑第一段 `Matched 4,881,888` / `Literal 37,061,152`，成功后暂存自动删除 |
| 中文 + 空格路径推送 | `中文 源/报告 数据.bin` → `A:/tmp/la-t/中文 目录/`，文件名与内容均正确（md5 一致） |
| 改名场景（目标名与源不同） | 源 `data` → 目标 `renamed`：两种中转都得 `B:/tmp/la-t2/renamed/data/data.bin`；重复执行结果不变 |

结论与两点新认识：

- **「同名即最终路径，不同名当容器」的规则在真实两机间成立**，tar 流与两段式 rsync 行为一致，重复执行幂等。
- **直拷的前提是「源机 → 目标机」免密**，不是「本机 → 两端」免密。A→B 没配免密时直拷会失败（`ssh -t` 会停在该提示上等输入）。所以直拷失败真不一定是网络问题。现在这件事由程序自己判断：点「开始拷贝」时先探「源机有 rsync 且免密可达目标机」，通了走直连，不通自动改走本机中转（后者只要求本机可达两端）。
- 中断现场在 `kill -9`（模拟断网/强杀）下同样保住半截文件，`--partial-dir` 不依赖 rsync 优雅退出。
