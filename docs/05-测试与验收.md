# AI 终端启动器 — 测试与验收

分两层：**Core 纯逻辑测试（可进 CI，无副作用）** + **GUI 冒烟/手工验收**。

## 1. 目录

| 文件 | 职责 |
|------|------|
| `src/Core.swift` | 纯逻辑层（仅 Foundation）：连接串解析、路径/主机拆分、shell 转义、命令拼装、配置读写、`~/.ssh/config` 解析、启动脚本生成 |
| `src/main.swift` | UI 层（AppKit）：窗口、滚动视图、按钮、弹窗、联想候选框、Terminal 启动 |
| `tests/main.swift` | Core 全量断言用例（纯命令行） |

## 2. Core 测试（默认入口）

```bash
./scripts/test.sh
```

等价于 `swiftc -O src/Core.swift tests/main.swift -o /tmp/ai-launcher-core-tests && /tmp/ai-launcher-core-tests`。
无 GUI、不弹 Terminal，失败返回非 0，可直接进 CI（`.github/workflows/ci.yml`）。

## 3. 编译检查

```bash
swiftc -O src/Core.swift src/main.swift -o /tmp/ai-launcher-check
file /tmp/ai-launcher-check
```

期望：Mach-O 可执行文件，退出码 0。这条不覆盖安装产物、也不杀正在跑的 `.app`。
安装路径验收用 `./scripts/build.sh`（会重启已打开的启动器）。

## 4. GUI 冒烟 `--selftest`（可选）

```bash
/tmp/ai-launcher-check --selftest
```

会真正启动窗口，1 秒后模拟点击第一个启动按钮（可能弹出 Terminal 跑配置里的第一个 CLI），断言互拷控件已构建、内容在滚动视图内、窗口可缩放、PATH 前缀与预设主机，约 5 秒后自动退出。日志 `/tmp/ai-launcher-debug.log`。

加 `--no-launch` 可跳过「点第一个启动按钮」，只做窗口/控件检查，不会弹 Terminal：

```bash
/tmp/ai-launcher-check --selftest --no-launch
```

纯逻辑断言已全部迁到 `tests/main.swift`，`--selftest` 不再承载回归职责，只做界面链路冒烟。**不带 `--no-launch` 时不要在无人值守环境跑**（会弹 Terminal）。

## 5. 手工验收（P0）

| 项 | 操作 | 期望 |
|----|------|------|
| 网格启动 | 点某个目录的 opencode | Terminal 工作目录为该路径 |
| 刷新 | 改 `dirs` 后点刷新 | 行数与名称变化，且互拷表单已填内容不丢 |
| 滚动 | 把窗口拖矮 | 出现竖向滚动条，底部「开始拷贝」可滚动到 |
| 本机→远端 | 小文件 push | 远端出现文件，成功关窗（且只关本 tab 窗口） |
| 解析 | 粘贴 `user@host` 点解析 | 用户名与 IP 回填，路径框不变 |
| 解析（端口） | 粘贴 `192.168.1.5:2222` 点解析 | 主机框 `192.168.1.5`、端口框 `2222`，用户名框为空 |
| 预设 | 选「预设」里的机器 | 连接串/用户名/主机被填上 |
| 联想 | 输入已配置免密 IP 的前几位后停手 | 弹出候选，可继续输入不被抢焦点；↑↓ 选择、回车采用 |
| 浏览远端 | 点「浏览远端」直接「列出」 | 状态栏「正在列出…」→ 弹出目录列表（默认 `~`） |
| 逐层浏览 | 选一个目录 →「进入下一层」→「上一级」 | 路径正确回退，不卡 UI |
| 非 22 端口拷贝 | 目标 `user@host:2222:/path` | Terminal 里 rsync 带 `-e "ssh -p 2222"` |
| 本机中转（tar 流） | 双远端填好、**不勾**「断点续传」后点「经本机中转」 | Terminal 执行 `ssh 源 'tar -cf -' \| ssh 目标 'tar -xf -'`，不占本地磁盘 |
| 本机中转（续传） | 双远端填好、**勾选**「断点续传」后点「经本机中转」；中途 Ctrl-C 再点一次同任务 | 两段 rsync；重跑那次从断点继续；成功后 `~/Library/Caches/ai-launcher/relay/<名>-<哈希>` 被删除 |
| 中转落点 | 源 `/tmp/src/data`、目标 `/tmp/dst/data`，两种中转各跑一次，再重复执行一次 | 结果都是 `/tmp/dst/data/{文件…}`；**不出现** `/tmp/dst/data/data`；两次结果一致 |
| 直连续传 | 200 MB 文件推远端，中途 Ctrl-C，再点「开始拷贝」 | 中断后目标侧只有 `.rsync-partial/big.bin`，最终路径为空；重跑只补剩余字节，完成后 md5 一致、`.rsync-partial` 自动清空 |
| 限速 | 「限速」填 `2`，传 60 MB 到远端 | 速度稳定在 ~2 MB/s（6 秒约 12 MB），日志里 `sent` 字节与时长相符 |
| 限速非法输入 | 填 `abc` 或 `-1` 后点「开始拷贝」 | 状态栏报错说明只接受数字，不会启动拷贝 |
| 日志落盘 | 任意一次拷贝后打开 `~/Library/Logs/ai-launcher/` | 有 `<源名>-<哈希>.log`，含 `[时间] 开始 …`、rsync 明细、`[时间] 结束，退出码 N`；状态栏显示该文件名 |
| 日志续跑累加 | 同一个任务中断后重跑，再看日志 | 同一文件里有两段记录（第一次带 `rsync error … SIGINT`，第二次成功），不覆盖 |
| 上次任务回填 | 拷贝一次后退出 app 再打开 | 源/目标/选项/限速自动回填，状态栏提示「已回填上次任务」；改一改路径再重启，回填的是改后的值 |
| PATH 可配置 | `pathPrepend` 加一个目录后刷新并启动 | 新 Terminal 里该目录在 PATH 首位 |

## 真实链路验证（无内网时也能做）

断言只验证「命令字符串长什么样」，验证不了「命令跑起来结果对不对」。2026-10-30 用下面这套方法真跑了一遍，才暴露出中转落点的两个 bug。手边没有可连的内网机器时，用本机 Docker 起一个临时 sshd 即可：

1. 本地镜像（Ubuntu）里装 `openssh-server` + `rsync`，把本机公钥放进 `/root/.ssh/authorized_keys`，`CMD sshd -D`
2. `docker run -d -p 2222:22` 起来，`ssh -p 2222 root@127.0.0.1` 能免密登录
3. 用一个包装脚本让「app 生成的命令」里的 `ssh` 读到临时配置：`PATH=/tmp/relay-bin:$PATH`，脚本内容为 `exec /usr/bin/ssh -F <临时 config> "$@"`（`HOME` 覆盖无效，OpenSSH 走 `getpwuid`）
4. 写个 10 行小程序链接 `src/Core.swift`，直接打印 `buildRelayCopyCommand` / `buildRelayResumeCommand` 的结果 —— 验证的就是线上那条命令，不手抄
5. 执行后 `find` 目标目录看层级、`md5sum` 比内容；续传场景用大文件跑 2 秒后 `pkill -f "rsync"`，再看 `.rsync-partial` 里的半截文件与重跑行为
6. 验证完 `docker rm -f` / `docker rmi`、删掉临时目录，并清 `~/Library/Caches/ai-launcher/relay` 里的测试残留

### 2026-10-30 直连续传实测（Docker + openssh + rsync 3.4.3）

200 MB 随机文件，限速 `--bwlimit=2000`（2 MB/s），6 秒后对 `rsync` 进程发 `SIGINT`：

| 观察项 | 旧参数 `--partial --append-verify` | 新参数 `--partial --partial-dir=.rsync-partial` |
|--------|-----------------------------------|--------------------------------------------------|
| 目标最终路径 | 出现 11.6 MB 的 `big.bin`（残缺，易被误判为传完） | 不出现文件 |
| 中断现场 | 直接落在最终文件名上 | `.rsync-partial/big.bin` 11.8 MB |
| 重跑 | 从头传（目标缺尾，追加无效） | `Matched data 11,826,672` / `Literal data 197,888,528`，只补剩余 |
| 完成后 | — | md5 与源一致，`.rsync-partial` 自动清空 |

复现要点：中断信号要打到 `rsync` 进程本身（`pkill -INT -f '<源路径>'`），只杀外层 subshell 的话 `rsync` 会继续跑完，看不到断点现场。

### 2026-10-30 限速与日志实测（Docker + openssh + rsync 3.4.3）

60 MB 随机文件，用 app 拼出的命令（`--bwlimit=2048 --log-file=…`）推远端，6 秒后打断：

| 观察项 | 结果 |
|--------|------|
| 限速是否生效 | `sent 12503969 bytes` / 6 秒 ≈ 2.08 MB/s，与 2 MB/s 设定一致（同一文件不限速时本地回环 1 秒内完成） |
| 中断现场 | `.rsync-partial/data.bin` 12.48 MB，最终路径无文件 |
| rsync 日志 | 有 `building file list`、`sent 12503969 bytes`、`rsync error: received SIGINT … (code 20)` |
| 重跑 | `sent 50459070 bytes`（只补剩余），md5 与源一致，`.rsync-partial` 自动清空；日志追加第二段，共 6 行 |
| 脚本层日志 | 成功：`[时间] 开始 …` / `[时间] 结束，退出码 0`；失败（`(exit 23)`）：记 `退出码 23` 并把 23 透出 |

两个坑：`--log-file` 的目录必须已存在（应用脚本里先 `mkdir -p`，手工验证时要自己建）；命令里若直接写 `exit N` 会跳过脚本末尾的日志收尾，真实拷贝命令是 rsync/tar 链不会这样，验证失败路径请用 `(exit N)` 子 shell。
