## 2. 本机现状（2026-10-29）

- 配置 `dirs` 指向本机若干 git 仓库；`tools` 为 `opencode` 与 `omp（Oh My Pi）`
- `copy.hosts` 仅少量 `user@host` 预设；约 25 台常用服务器的免密在 SSH 配置里，互拷联想走那份清单
- Debug 日志：`/tmp/ai-launcher-debug.log`
- 应用名：`AI终端启动器`（2026-10-29 从「AI启动器菜单栏」更名），Bundle ID `local.ai-launcher.desktop`
- 签名：本机无 Apple 开发者证书，`scripts/sign-app.sh` 走 ad-hoc；`build.sh` 与 `package.sh` 都会调用。**不要跳过签名**，否则 bundle 签名与 linker 自动签名不一致，从网上下载会报「已损坏」（G-18）

## 3. 接手后第一件事

```bash
cd ~/Desktop/git/ai-launcher
swiftc -O src/Core.swift src/main.swift -o /tmp/ai-launcher-check && file /tmp/ai-launcher-check
./scripts/test.sh   # Core 311 条断言，无 GUI 副作用
ls ~/Applications/AI终端启动器.app/Contents/MacOS/
ls ~/.config/ai-launcher/config.json
```

改源码后：

```bash
./scripts/build.sh          # 编译 + 签名 + 装到 ~/Applications 并重启
./scripts/package.sh        # 打可分发的 DMG/zip（universal），产物在 dist/
```

分发给他人、签名与公证的完整说明见 [08-分发与安装.md](08-分发与安装.md)。

不要把 `config.json` 拷进仓。对照 [config.example.json](../config.example.json) 改本机副本。

## 4. 改代码时要守的边界

- 密码不得写入 `.command`、日志明文、Git（`last-copy.json` 也只存路径与选项，不存密码）
- 启动 CLI 继续走 `.command` + `open`，不要改回 AppleScript 点 Terminal（会要 TCC）
- 互拷方向继续由路径推导，不要加回易点错的方向控件除非需求变更
- `Info.plist` 与二进制必须同包；只换 Mach-O 时沿用现有 plist 即可
- 续传参数保持 `--partial --partial-dir=.rsync-partial`，不要换回 `--append-verify`（实测会把残缺文件留在最终路径）
- 程序不写 `config.json`；要持久化状态就新开文件（如 `last-copy.json`），别改用户手写的配置格式
- 构建产物必须签名（`scripts/sign-app.sh`），且签完要 `codesign --verify --deep --strict` 校验通过；签名损坏比不签更容易被判「已损坏」
- 打包脚本里所有 staging 目录每次重建，不要复用：残留的 `Applications` 是符号链接，`ln -s` 会跟进去污染真实 `/Applications`

## 6. 回滚

- 只回滚源码：在本仓 `git checkout`（初始化后）再 `./scripts/build.sh`
- 只回滚安装：保留旧 `.app` 备份再覆盖
- 配置损坏：删 `config.json` 后重启，应用会按 `defaultConfigJSON()` 重建（内容仍是本机缺省，不是 example）
