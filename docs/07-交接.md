# AI 终端启动器 — 交接

接手后按本文能编译、改配置、继续改源码。沿革见 [形成过程.md](形成过程.md)。

## 1. 职责切分

| 对象 | 路径 | 谁维护 |
|------|------|--------|
| 源码、文档、示例配置、构建脚本 | `~/Desktop/git/ai-launcher/` | 本仓 |
| 安装产物 | `~/Applications/AI启动器菜单栏.app` | `scripts/build.sh` 覆盖二进制；不要当源码改 |
| 运行时配置 | `~/.config/ai-launcher/config.json` | 本机，不提交 |
| 免密主机 | `~/.ssh/config` 与 `~/.ssh/` 密钥 | 本机，不提交 |
| 旧源码目录 | `~/Applications/AI启动器菜单栏-src/` | 只留跳转，禁止再改 |

办公仓 `AI办公目录` 不托管本工具源码。周报里出现的「AI 终端启动器」只是工作记录，不是本仓文档正本。

## 2. 本机现状（2026-10-29）

- 配置 `dirs` 指向本机若干 git 仓库；`tools` 为 `opencode` 与 `omp（Oh My Pi）`
- `copy.hosts` 仅少量 `user@host` 预设；约 25 台常用服务器的免密在 SSH 配置里，互拷联想走那份清单
- Debug 日志：`/tmp/ai-launcher-debug.log`
- Bundle ID：`local.ai-launcher.menubar`，未公证签名

## 3. 接手后第一件事

```bash
cd ~/Desktop/git/ai-launcher
swiftc -O src/Core.swift src/main.swift -o /tmp/ai-launcher-check && file /tmp/ai-launcher-check
./scripts/test.sh   # Core 124 条断言，无 GUI 副作用
ls ~/Applications/AI启动器菜单栏.app/Contents/MacOS/
ls ~/.config/ai-launcher/config.json
```

改源码后：

```bash
./scripts/build.sh
```

不要把 `config.json` 拷进仓。对照 [config.example.json](../config.example.json) 改本机副本。

## 4. 改代码时要守的边界

- 密码不得写入 `.command`、日志明文、Git
- 启动 CLI 继续走 `.command` + `open`，不要改回 AppleScript 点 Terminal（会要 TCC）
- 互拷方向继续由路径推导，不要加回易点错的方向控件除非需求变更
- `Info.plist` 与二进制必须同包；只换 Mach-O 时沿用现有 plist 即可

办公仓内与本工具直接相关、且适合进本仓的材料：

| 来源 | 处理 |

没有单独成文的旧「交接.md」或「现状.md」可物理搬迁；这两份正是本文与 [06-已知缺口与后续.md](06-已知缺口与后续.md)。

## 6. 回滚

- 只回滚源码：在本仓 `git checkout`（初始化后）再 `./scripts/build.sh`
- 只回滚安装：保留旧 `.app` 备份再覆盖
- 配置损坏：删 `config.json` 后重启，应用会按 `defaultConfigJSON()` 重建（内容仍是本机缺省，不是 example）
