# AI 终端启动器 — 已知缺口与后续

本文是**现状与缺口**，不替代 [04-使用说明.md](04-使用说明.md)。待办未做不等于已经解决。

## 当前结论

- 日常启动 CLI 与互拷已在本机使用：窗口网格、配置刷新、`.command` 启 Terminal、rsync/scp、连接串解析、免密联想、远端逐层浏览、本机中转。
- 源码分两层：`src/Core.swift`（纯逻辑，Foundation only）+ `src/main.swift`（AppKit UI）。
- Core 有全量命令行断言（`./scripts/test.sh`，无 GUI 副作用，条数见 [05-测试与验收.md](05-测试与验收.md)），并有 GitHub Actions CI；`--selftest` 仅做 GUI 冒烟（加 `--no-launch` 不会点按钮、不弹 Terminal）。
- 安装产物 `~/Applications/AI终端启动器.app`；真实配置仍是 `~/.config/ai-launcher/config.json`。
- 跨机链路 2026-11-03 已在两台真实内网机上验过（推送 / 拉取 / 中断续传 / 断网强杀 / 直拷 / 两种中转 / 中文路径 / 改名幂等），数据见 [05-测试与验收.md](05-测试与验收.md)。此前只在单容器 Docker 里验过，本轮无代码改动。
- 周报 2026-10-25 已记录互拷与约 25 台免密主机。现行 `config.json` 的 `copy.hosts` 只保留少量预设，完整主机清单在 `~/.ssh/config`，不进本仓。

## 已交付（对照源码，不是历史口号）

|----|------|
| 目录 × CLI 启动 | `loadConfig` + 按钮 `launchTool` |
| 外部 JSON 配置 | `~/.config/ai-launcher/config.json`，刷新重建窗口（并保留表单内容） |
| 可配置 PATH | `pathPrepend` + `buildPathExport`/`buildCommandScript`，不再硬编码 bun/Homebrew |
| 免 TCC 启 Terminal | 临时 `.command` + `open` |
| 精确关窗 | 脚本内记 `tty`，成功时只关该 tty 所在窗口 |
| 互拷四向 | `deriveDirection`：push / pull / direct / local |
| 连接串 | `parseConnection` 含主机在前的表格格式、`IP:端口` 正确识别、IPv6 方括号 |
| 免密预设 | `copy.hosts` → 互拷「预设」下拉 |
| 免密联想 | `loadSSHKnownHosts` + 非阻塞 `NSPopover` 候选（去抖 0.15s、↑↓/回车/Esc、按 mtime 重载） |
| 远端浏览 | `sshListDir` 后台执行 + 逐层进入/上一级，仅 BatchMode 密钥 |
| 直拷兜底 | 后台自动选路：先探「源机有 rsync 且免密可达目标机」，通就直连、不通自动中转（`resolveDirectRoute`），不给用户开关 |
| 断点续传 | 直连（push/pull/双远端）与自动中转统一 `--partial --partial-dir=.rsync-partial`，中断现场不落最终路径 |
| 限速 | 互拷选项行「限速 MB/s」→ rsync `--bwlimit` / scp `-l`；非法输入报错不静默 |
| 传输日志 | `~/Library/Logs/ai-launcher/<源名>-<哈希>.log`：rsync `--log-file` 明细 + 脚本层开始/结束/退出码，同一任务追加 |
| 上次任务回填 | `~/.config/ai-launcher/last-copy.json`，重启后表单为空即回填，续传不用重填路径 |
| 填充不串框 | `buildFillPlan` 按触发框填（已迁入 Core 并可测） |
| 密码不落盘 | `startCopy` 故意不读密码框进命令；日志脱敏 |
| 自定义端口互拷 | `buildCopyCommand` 拆端口 → `-e "ssh -p N"` / `scp -P N` |
| 可测逻辑层 | `src/Core.swift` + `tests/main.swift` + `scripts/test.sh` + CI |
| 窗口可用性 | `NSScrollView` 滚动 + 可缩放，高度限制在屏幕内 |
| 打包分发 | `scripts/package.sh` 出 universal DMG/zip + SHA256；`sign-app.sh` 补签名（Developer ID 或 ad-hoc）；`install-remote.sh` 一行装；推 tag 自动发 Release |

### 2026-11-03（真实跨机验证，无代码改动）

| 项 | 结论 |
|----|------|
| 跨机链路 | 两台真实内网机（rsync 3.2.7 / GNU tar 1.34）跑通推送、拉取、两种中转、中文+空格路径；md5 全部一致 |
| 续传现场 | SIGINT 与 `kill -9`（模拟断网）两种中断下，半截都只落目标侧 `.rsync-partial`，最终路径无残缺文件；重跑 `Matched` 字节数与半截大小一致 |
| 落点规则 | 「同名即最终路径 / 不同名当容器」在两机间成立，tar 流与两段式 rsync 一致，重复执行不套娃 |
| 直拷前提 | 直拷要求**源机 → 目标机**免密；A→B 未配免密时直拷失败，真实 tty 下能看到密码提示（`ssh -t` 生效）。这条结论直接催生了 G-20：把「源机能不能到目标机」变成后台探测，而不是让用户猜 |

### 2026-11-10（中转改为自动判断，G-20）

| 项 | 处理 |
|----|------|
| 用户要的是结果，不是选路 | 去掉「经本机中转」按钮与 `startRelayCopy`；双远端统一走 `startCopy` → `startDirectResolve`（后台探测，主线程只更新状态栏与按钮可用性） |
| 探测什么 | `buildDirectProbeCommand`：外层 `ssh` 到源机，源机上先 `command -v rsync` 再 `ssh` 目标机 `true`，两层都 `BatchMode=yes` + `ConnectTimeout=5`。任一不成立即判直连不通 |
| 不通怎么办 | `buildLocalProbeCommand` 验本机能否登两端；能 → `resolveDirectRoute` 返回 `.relayResume`（勾续传且本机有 rsync）或 `.relayTar`；不能 → `.unreachable`，状态栏明确报「两端都不可达」 |
| 不写别人的 known_hosts | 探测故意不加 `StrictHostKeyChecking=accept-new`：首次连接遇未知主机键就判不通，改走中转即可，绝不在别人服务器上留指纹 |
| 顺带修的隐患 | `hasRsync()` 只看命令存在；macOS 15 起 `/usr/bin/rsync` 是 openrsync（本机实测 `--info=progress2` → `unrecognized option`）。新增 `RsyncFlavor`（none/openRsync/full），`buildCopyCommand` 与 `buildRelayResumeCommand` 按能力决定是否拼 `--info=progress2` / `--log-file`，状态栏也会说明「系统自带 openrsync」 |
| 实测 | 容器 sshd 三态验证：源机有 rsync 且免密 → `rc=0`（0.29s，判直连）；卸掉 rsync → `rc=127`（判不通 → 中转）；目标不可达 → `rc=255`（5.0s 超时退出，不卡 UI） |
