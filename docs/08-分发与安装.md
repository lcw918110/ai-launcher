# 分发与安装

面向「把这台机器上的应用装到别人机器上」。本机自用不需要看这里，`./scripts/build.sh` 就够了。

## 1. 为什么别人装会提示「已损坏」

macOS 对从**浏览器**下载的文件会打一个扩展属性 `com.apple.quarantine`。带这个标记的 `.app` 启动前必须过 Gatekeeper 检查，检查不过就拦。

拦下来的提示有两种，含义完全不同：

| 提示 | 底层原因 | 能否绕过 | 怎么办 |
|------|----------|----------|--------|
| **「已损坏，应将其移到废纸篓」** | 代码签名本身坏了 | 不能 | 必须重新签，见下 |
| 「无法验证开发者」 | 签名有效，但没有 Apple 公证 | 能 | 系统设置里放行，或装的时候清标记 |

第一种的根因很具体。arm64 上链接器会给二进制自动打一个 ad-hoc 签名，这个签名里声明了「bundle 应带 `_CodeSignature/CodeResources`」；而手工组装的 `.app`（`mkdir` + `cp` + `swiftc`，没有 Xcode 打包步骤）没有这个文件。于是 `codesign` 报：

```
code has no resources but signature indicates they must be present
```

Gatekeeper 看到签名自相矛盾，直接判定损坏。这就是 0.4.4 及以前从 GitHub 下载会被拦的原因。

**修法**：给 bundle 补一次签名，让签名和实际内容一致。0.4.5 起 `scripts/sign-app.sh` 在每次构建后执行这一步。

实测对照（macOS 26.6.2，两包都打了 quarantine，`spctl -a -t exec -vv`）：

| | 修之前 | 修之后（ad-hoc 签名） |
|---|---|---|
| `codesign --verify` | `code has no resources but signature indicates they must be present` | 通过（退出码 0） |
| `spctl` | 同上错误 | `rejected` |
| 用户看到的 | 已损坏 | 无法验证开发者（可放行） |

注意 ad-hoc 签名**不能**消除提示，它只是把「死路」换成「有出口」。要彻底没提示，得清 quarantine 或者买证书公证。

## 2. 三种分发方式

### 方式一：命令行一键安装（推荐，零提示）

```sh
curl -fsSL https://raw.githubusercontent.com/lcw918110/ai-launcher/main/scripts/install-remote.sh | zsh
```

装完直接打开，没有任何弹窗。原理：`curl` 不经过 LaunchServices，下载的文件不带 `com.apple.quarantine`；脚本拷完还会再清一次属性兜底。Gatekeeper 只检查带标记的文件，没标记就不拦。

可配环境变量：

| 变量 | 作用 | 示例 |
|------|------|------|
| `AI_LAUNCHER_VERSION` | 装指定版本（默认 latest），`v0.4.5` / `0.4.5` 都认 | `AI_LAUNCHER_VERSION=0.4.5 ...` |
| `AI_LAUNCHER_MIRROR` | 换下载源（内网镜像、私有部署） | `AI_LAUNCHER_MIRROR=http://10.0.0.5/releases ...` |
| `AI_LAUNCHER_DEST_DIR` | 指定安装目录（默认 `/Applications`，不可写则退到 `~/Applications`） | `AI_LAUNCHER_DEST_DIR=/opt/apps ...` |
| `AI_LAUNCHER_NO_OPEN` | 设 1 则只装不启动（批量部署） | `AI_LAUNCHER_NO_OPEN=1 ...` |

装之前可以先看脚本内容，`curl` 下来再执行，不必直接管道进 shell。

### 方式二：DMG 手动安装（给习惯图形界面的同事）

1. 下载 `ai-launcher-<版本>.dmg`，双击挂载
2. 把「AI终端启动器」拖进 Applications 软链，**或**双击 DMG 里的 `安装到应用程序文件夹.command`
3. 若上一步是手动拖的，在终端补一行：

```sh
xattr -dr com.apple.quarantine "/Applications/AI终端启动器.app"
```

DMG 里附了 `首次打开说明.txt`，写的是同样几步，省得口头教。

那个 `.command` 本身也会被 Gatekeeper 问一次「确定要打开吗」，点确认即可；它做的事就是拷贝 + 清标记 + 校验签名。

### 方式三：zip（内网 / scp）

`ai-launcher-<版本>.zip` 用 `ditto` 打包，保留了资源叉和可执行权限，`scp` 过去解压即可。同样需要清 quarantine，否则会看到「无法验证开发者」。

## 3. 打包

```sh
./scripts/package.sh          # 版本取自 src/Info.plist
./scripts/package.sh 0.5.0    # 临时覆盖版本号，不改 plist
```

产物在 `dist/`（已在 `.gitignore`）：

| 文件 | 用途 |
|------|------|
| `AI终端启动器-<版本>.dmg` | 主分发物（~500 KB），含说明与安装脚本 |
| `AI终端启动器-<版本>.zip` | 内网 / scp |
| `SHA256SUMS.txt` | 校验和，`shasum -a 256 -c SHA256SUMS.txt` |

特点：

- **universal**：分别按 `arm64` / `x86_64` 编译再 `lipo` 合并，Intel 机器也能跑（`lipo -archs` 显示 `x86_64 arm64`）
- 每次从干净目录开始组装，不复用上次的 staging（踩过坑：残留的 `Applications` 是符号链接，`ln -s` 会跟进去，在真实 `/Applications` 里建链接）
- 打包不碰 `~/Applications`，可安全地在 CI 上跑

## 4. 签名：现在是什么，以后怎么升级

`scripts/sign-app.sh` 会自动判断：

| 条件 | 行为 | 命令 |
|------|------|------|
| 有 `Developer ID Application` 证书（或用 `DEVELOPER_ID` 环境变量指定） | 真签名，带 hardened runtime 与时间戳 | `codesign --force --deep --options runtime --timestamp --sign "$ID"` |
| 没有证书 | ad-hoc | `codesign --force --deep --sign -` |

签名后立刻 `codesign --verify --deep --strict` 校验，不通过就中止打包——不能把坏包发出去。

**想彻底消除提示**，需要 Apple Developer Program（$99/年）后补两步：

```sh
# 1. 打包时用真证书（package.sh 会自动识别本机证书）
DEVELOPER_ID="Developer ID Application: Your Name (TEAMID)" ./scripts/package.sh

# 2. 公证 + 装订
xcrun notarytool submit "dist/AI终端启动器-<版本>.dmg" \
      --apple-id "you@example.com" --team-id "TEAMID" \
      --password "app-specific-password" --wait
xcrun stapler staple "dist/AI终端启动器-<版本>.dmg"
```

公证要求 hardened runtime（脚本已带 `--options runtime`）。公证过的包，用户双击会看到「已验证开发者」，不再需要清 quarantine。

CI 里要真签名的话，把证书导成 base64 存 `secrets`，在 release workflow 里 `security import`，再设 `DEVELOPER_ID` 和 `--require-dev-id`（后者让签名在缺证书时直接失败，避免悄悄降级成 ad-hoc）。

## 5. 自动发布

`.github/workflows/release.yml`，推 `v*` 标签时触发：

1. 先跑 `scripts/test.sh`（测试不过不发版）
2. `./scripts/package.sh` 构建 universal 包并签名（CI 上无证书，产物是 ad-hoc）
3. 上传资产，文件名转 ASCII 便于 URL 引用：
   - `ai-launcher-<版本>.dmg` / `ai-launcher-<版本>.zip`
   - `ai-launcher-latest.dmg`（固定名，`releases/latest/download/` 才能稳定取到）
   - `SHA256SUMS.txt`

`.github/workflows/ci.yml` 只跑分支，tag 交给 release workflow，避免重复执行。

## 6. 排障

| 现象 | 原因 | 处理 |
|------|------|------|
| 「已损坏，应移到废纸篓」 | 下载的是 0.4.4 及以前的包（bundle 未签名） | 换 0.4.5+ 的包；或本地 `codesign --force --deep --sign - <app>` 自己补签 |
| 「无法验证开发者」 | ad-hoc 签名，无公证，属预期 | 清 quarantine，或系统设置放行 |
| 系统设置里找不到「仍要打开」 | macOS 15 起该入口只在拦截发生后短暂出现 | 先双击一次让对话框出现，再进设置页底部 |
| 装完打不开、闪退 | 二进制架构不匹配或被杀软拦截 | `lipo -archs` 确认含本机架构；`codesign --verify` 看签名 |
| `codesign --verify` 报 `code has no resources` | bundle 缺 `_CodeSignature`，即未签 | 跑 `./scripts/sign-app.sh <app>` |
| 覆盖安装后行为没变 | 旧进程还在跑 | 脚本已 `pkill -x` 处理；手动装的话先退出应用 |
