# AI 终端启动器 — 架构设计

分成两层，无 Swift Package：

| 文件 | 层 | 依赖 | 可否单独测 |
|------|----|------|------------|
| `src/Core.swift` | 纯逻辑：解析、转义、命令拼装、配置读写、`~/.ssh/config` | 仅 Foundation | 是（`tests/main.swift`） |
| `src/main.swift` | UI：窗口、按钮、弹窗、Terminal 启动 | AppKit | 仅 GUI 冒烟 |

包标识 `local.ai-launcher.menubar`。分层的目的不是好看，而是让互拷/解析逻辑能脱离 GUI 跑断言（见 [05-测试与验收.md](05-测试与验收.md)）。

## 1. 运行时三件套

```text
本仓 src/{Core,main}.swift  --build.sh-->  ~/Applications/AI启动器菜单栏.app
                                                │
                                                ▼
                                        ~/.config/ai-launcher/config.json
                                                │
                                                ▼
                                   /tmp/ai-launcher-*.command  -->  Terminal.app
```

| 层 | 位置 | 是否进 Git |
|----|------|------------|
| 源码与文档 | 本仓 | 是 |
| 安装产物 | `~/Applications/AI启动器菜单栏.app` | 否 |
| 本机配置 | `~/.config/ai-launcher/config.json` | 否，仓内只有 [config.example.json](../config.example.json) |
| 免密主机 | `~/.ssh/config` | 否 |
| 调试日志 | `/tmp/ai-launcher-debug.log` | 否 |

## 2. 进程与窗口

- `NSApplication` + `AppDelegate`，标准 Dock 应用（未设 `LSUIElement`）
- 主窗口 `isReleasedWhenClosed = false`，关闭后点 Dock 图标走 `applicationShouldHandleReopen`
- 窗口内容每次 `buildWindow()` 整树重建：标题、目录×CLI 行、「其他目录」、刷新、互拷区块

## 3. 配置加载

- `ensureConfigExists()`：目录不存在则创建；文件不存在则把 `defaultConfigJSON()` 写出
- `loadConfig(path:)` 读 `dirs` / `tools`；解析失败回落到同一套缺省
- `loadCopyConfig(path:)` 读可选 `copy` 段；`defaultDirection` / `auth` 为废弃键，读取时忽略

`defaultConfigJSON()` 只含占位路径（`/path/to/project-a`）与空 hosts，首次启动不会写出任何本机/内网信息；日常以用户主目录下的 JSON 为准。

## 4. 启动命令

`launchInTerminal` 拼：

```text
cd '<dir>' && export PATH="$HOME/.bun/bin:/opt/homebrew/bin:$PATH" && clear && exec <cmd>
```

`launchCommandInTerminal` 再包一层 zsh 脚本写成 `.command`。互拷另加完成回显；`autoCloseOnSuccess` 为真时用 `osascript` 关 Terminal 前窗。

不把用户密码拼进这串命令。

## 5. 互拷命令

`deriveDirection` 看源、目标是否 `isRemotePath`（含 `:` 且冒号前无 `/`，且不以 `/` 开头）。

`buildCopyCommand(cfg:params:rsyncAvailable:)`：

- 两端都远端：`ssh -t [-p 源端口] <源host> 'rsync … [-e "ssh -p 目标端口"] <源path> <目标user@host:path>'`
- 否则优先 `rsync`，无则 `scp`
- 自定义端口：`user@host:port:path` 经 `splitRemoteSpec` 拆成 host/port/path，端口转 `-e "ssh -p N"`（rsync）或 `-P N`（scp）——rsync/scp 本身不支持冒号端口写法
- `rsyncAvailable` 由调用方 `hasRsync()` 探测后传入，函数本身无副作用、可测

路径经 `shellQuote` 单引号转义；远端 `ls` 的路径用 `remotePathArg`（`~` 必须裸写才能被远端 shell 展开）。

## 6. 免密与浏览

- `loadSSHKnownHosts(path:)` 行扫描 `~/.ssh/config`
- 联想在 `controlTextDidChange`，用 `NSMenu.popUp`
- `sshListDir`：`/usr/bin/ssh`，`BatchMode=yes`，`ConnectTimeout=8`；调用方在后台队列执行，避免卡住主线程；管道先读完再 `waitUntilExit`，防止大目录死锁

填充决策 `buildFillPlan` 是 Core 里的纯函数，与 UI 状态分离，由 `tests/main.swift` 覆盖串框场景。

## 7. 构建

[scripts/build.sh](../scripts/build.sh) 调用 `swiftc -O src/Core.swift src/main.swift`，输出到 `.app/Contents/MacOS/`；每次构建都覆盖 `.app` 的 `Info.plist`；用 `pgrep/pkill -x` 精确匹配进程名重启。不签名。
