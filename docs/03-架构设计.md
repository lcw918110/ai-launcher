# AI 终端启动器 — 架构设计

分成两层，无 Swift Package：

| 文件 | 层 | 依赖 | 可否单独测 |
|------|----|------|------------|
| `src/Core.swift` | 纯逻辑：解析、转义、命令拼装、配置读写、`~/.ssh/config`、启动脚本生成 | 仅 Foundation | 是（`tests/main.swift`） |
| `src/main.swift` | UI：窗口、滚动视图、按钮、弹窗、联想候选框、Terminal 启动 | AppKit | 仅 GUI 冒烟 |

包标识 `local.ai-launcher.desktop`（2026-10-29 从 `local.ai-launcher.menubar` 更名）。分层的目的不是好看，而是让互拷/解析逻辑能脱离 GUI 跑断言（见 [05-测试与验收.md](05-测试与验收.md)）。

## 1. 运行时三件套

```text
本仓 src/{Core,main}.swift  --build.sh-->  ~/Applications/AI终端启动器.app
                                                │
                                                ▼
                                        ~/.config/ai-launcher/config.json
                                                │
                                                ▼
                                   /tmp/ai-launcher-*.command  -->  Terminal.app
```

| 层 | 位置 | 是否进 Git |
|----|------|------------|
| 源码与文档 | 本仓 | 是 |
| 安装产物 | `~/Applications/AI终端启动器.app` | 否 |
| 本机配置 | `~/.config/ai-launcher/config.json` | 否，仓内只有 [config.example.json](../config.example.json) |
| 免密主机 | `~/.ssh/config` | 否 |
| 调试日志 | `/tmp/ai-launcher-debug.log` | 否 |

## 2. 进程与窗口

- `NSApplication` + `AppDelegate`，标准 Dock 应用（未设 `LSUIElement`）
- 主窗口 `isReleasedWhenClosed = false`，关闭后点 Dock 图标走 `applicationShouldHandleReopen`
- 窗口内容每次 `buildWindow()` 整树重建：标题、目录×CLI 行、「其他目录」、刷新、互拷区块
- 内容放在 `NSScrollView` 里，文档视图是 `FlippedView`（翻转坐标，内容从顶部排）；`stack` 四边贴文档视图，宽度跟随窗口，高度由内容决定
- 窗口 `.resizable`，最小 480×320，初始高度 `min(内容高, 屏幕可用高 - 80)`，项目再多也不会溢出屏幕

## 3. 配置加载

- `ensureConfigExists()`：目录不存在则创建；文件不存在则把 `defaultConfigJSON()` 写出
- `loadConfig(path:)` 读 `dirs` / `tools`；解析失败回落到同一套缺省
- `loadCopyConfig(path:)` 读可选 `copy` 段；`defaultDirection` / `auth` 为废弃键，读取时忽略
- `loadPathPrepend(path:)` 读 `pathPrepend`：缺键 → `defaultPathPrepend`；显式 `[]` → 不注入任何目录

`defaultConfigJSON()` 只含占位路径（`/path/to/project-a`）、空 hosts 与缺省 `pathPrepend`，首次启动不会写出任何本机/内网信息；日常以用户主目录下的 JSON 为准。

### 本地状态文件（程序自己写，不碰用户手写的 config）

| 文件 | 内容 | 谁写 | 说明 |
|------|------|------|------|
| `~/.config/ai-launcher/config.json` | `dirs` / `tools` / `copy` / `pathPrepend` | 用户手写 | 程序只读（首次缺失时写一份占位模板），**不会回写**，格式与注释不会被程序改掉 |
| `~/.config/ai-launcher/last-copy.json` | 上次互拷的源/目标/选项/限速 | `saveCopyMemory` | 启动时表单为空则回填，保证「重启后还能接着续传」；不存密码 |
| `~/Library/Logs/ai-launcher/<源名>-<哈希>.log` | rsync 明细 + 开始/结束/退出码 | rsync `--log-file` + 脚本 | 哈希由「源 + 目标」决定，同一任务多次运行追加到同一文件 |
| `~/Library/Caches/ai-launcher/relay/<源名>-<哈希>/` | 中转暂存 | `buildRelayResumeCommand` | 成功后自动删除，失败保留供续传 |

`CopyMemory` 与 config 分开的理由：config 是给人编辑的，程序回写会破坏注释、键顺序和用户习惯；状态文件可以随便覆盖。

## 4. 启动命令

`launchInTerminal` 拼 `cd '<dir>' && clear && exec <cmd>`，PATH 不再写死在命令里，而由 `buildPathExport` 生成一行：

```text
export PATH="$HOME/.bun/bin:/opt/homebrew/bin:/usr/local/bin:$PATH"
```

`buildCommandScript(cmdLine:pathPrepend:autoCloseOnSuccess:logPath:startNote:)`（Core，纯函数）产出完整 `.command` 内容：

```text
#!/bin/zsh
<PATH 行>            # pathPrepend 为空时省略
_tty=$(tty 2>/dev/null)
mkdir -p <日志目录>                      # 仅 logPath 非空
printf '[%s] 开始 %s\n' "$(date …)" <任务摘要> >> <日志>   # 仅 logPath 非空
<命令行>
_rc=$?                                   # 需要记日志或关窗时才取
printf '[%s] 结束，退出码 %d\n' "$(date …)" "$_rc" >> <日志>  # 仅 logPath 非空
<完成回显 + 按 tty 关窗>                  # 仅 autoCloseOnSuccess
exit $_rc
```

日志分两层：rsync 自己的 `--log-file` 记传输明细（哪些文件、发了多少字节、错误码），脚本层记「这次运行是什么任务、什么时候、退出码多少」。两者写同一个文件，续传的多次运行会按时间追加在一起。

`launchCommandInTerminal` 只负责写文件、`chmod 755`、`open`。脚本语法在测试里用 `zsh -n` 校验。

关窗不用 `front window`，而是取脚本所在 tab 的 `tty`，在 AppleScript 里遍历 `windows` 匹配 `tty of selected tab`，命中才 `close … saving no`；匹配不到就不关，避免误关用户其它窗口。

不把用户密码拼进这串命令。

## 5. 互拷命令

`deriveDirection` 看源、目标是否 `isRemotePath`（含 `:` 且冒号前无 `/`，且不以 `/` 开头）。远端规格的 host/path 边界统一走 `remoteHostSepIndex`，兼容 `user@[::1]:path`。

`buildCopyCommand(cfg:params:rsyncAvailable:logPath:)`：

- 两端都远端：`ssh -t [-p 源端口] <源host> 'rsync … [-e "ssh -p 目标端口"] <源path> <目标user@host:path>'`
- 否则优先 `rsync`，无则 `scp`
- 续传：勾选时三条 rsync 路径都加 `--partial --partial-dir=.rsync-partial`。**不用 `--append-verify`**——它要求目标是源的前缀，中断时会把半截文件直接留在最终路径（2026-10-30 实测：200 MB 传 6 秒中断后目标路径出现 11.6 MB 的 `big.bin`，下游会误判传完），且目标被改短时会先追加垃圾再靠校验发现，等于白传一遍
- 限速：`CopyParams.bwlimitKbps`（0 = 不限）→ rsync `--bwlimit=<kbps>`；scp 降级用 `-l <kbps×8>`（scp 的单位是 Kbit/s）。UI 输入的是 MB/s，由 `parseBwlimitMBps` 换算，非法返回 `nil` 让调用方报错
- 日志：`logPath` 非空时给**本机发起**的 rsync 加 `--log-file`。双远端直拷在源机执行、tar 流没有 `--log-file`，这两条路径只由脚本层记时间与退出码
- 自定义端口：`user@host:port:path` 经 `splitRemoteSpec` 拆成 host/port/path，端口转 `-e "ssh -p N"`（rsync）或 `-P N`（scp）——rsync/scp 本身不支持冒号端口写法
- `rsyncAvailable` 由调用方 `hasRsync()` 探测后传入，函数本身无副作用、可测

`buildRelayCopyCommand(params:)`（直拷兜底，tar 流）：

```text
ssh [-p 源端口] <源host> 'tar -cf - -C <源父目录> <条目>' | ssh [-p 目标端口] <目标host> 'mkdir -p <解包目录> && tar -xf - -C <解包目录>'
```

流式经过本机，不依赖源机 rsync、不占本地磁盘；`splitDirAndName` 负责拆目录/条目名。

解包目录的取法（`buildRelayCopyCommand` 与 `buildRelayResumeCommand` 共用同一规则，保证两种模式落点一致）：

```text
解包目录 = (目标末段 == 源条目名) ? 目标父目录 : 完整目标路径
```

- 目标末段与源同名（`/data/report` → `/backup/report`）：解到 `/backup`，结果就是目标路径本身
- 不同名（`/data/report` → `/backup`）：解到 `/backup`，结果 `/backup/report`（目标当容器）

两条路径都幂等。**踩过的坑**：打包的条目是源目录本身，若一律解到完整目标路径，`/tmp/dst/data` 会变成 `/tmp/dst/data/data`，重复执行继续套娃——这是 2026-10-30 真实链路验证时发现的。

`buildRelayResumeCommand(params:root:)`（直拷兜底，可续传）：

```text
mkdir -p <暂存> && \
rsync [-r][-a] --partial --partial-dir=.rsync-partial --info=progress2 [-e 'ssh -p 源端口'] <源host>:<源路径> <暂存>/ && \
rsync [-r][-a] --partial --partial-dir=.rsync-partial --info=progress2 [-e 'ssh -p 目标端口'] \
      --rsync-path='mkdir -p <目标目录> && rsync' <暂存>/<条目> <目标host>:<目标目录>/ && \
echo '中转完成，清理本机暂存' && rm -rf <暂存>
```

- 目标写「目录 + 尾斜杠」，目录按上面的同名/不同名规则取，落点为 `<目录>/<条目>`，与 tar 流完全一致，重复执行只同步不嵌套
- `--rsync-path` 让远端先建该目录：rsync 自己不会创建缺失的父目录（否则报 `mkdir failed: No such file or directory`）
- 暂存目录名由 `shortHash(源规格 + "|" + 目标规格)` 决定，同一对源/目标稳定同名，重跑才能续传；换任一端就是新任务
- `&&` 串联：任一段失败后续不执行，暂存保留待下次续传；全部成功才清理
- 半截文件进 `.rsync-partial`，rsync 以它为基底做增量；比 `--append-verify` 安全（目标被改短时不会写坏）
- 是否走这条路径由 UI 决定：勾选「断点续传」且 `hasRsync()` 为真才用，否则回落 tar 流

路径经 `shellQuote` 单引号转义；远端 `ls` 的路径用 `remotePathArg`（`~` 必须裸写才能被远端 shell 展开）。

## 6. 免密、联想与浏览

- `loadSSHKnownHosts(path:)` 行扫描 `~/.ssh/config`
- 联想：`controlTextDidChange` 只记字段并起 0.15s 去抖计时器；到点后用 `NSPopover` + `NSTableView`（`SuggestionController`）展示候选，不进入菜单的事件追踪循环，因此不会抢键盘
- 键盘接管在 `control(_:textView:doCommandBy:)`：`moveDown/moveUp` 移动高亮，`insertNewline/insertTab` 采用，`cancelOperation` 收起
- 缓存用 `fileModificationDate(~/.ssh/config)` 比对 mtime，文件改了下次输入即重载，无需重启
- `sshListDir`：`/usr/bin/ssh`，`BatchMode=yes`，`ConnectTimeout=8`；调用方在后台队列执行；管道先读完再 `waitUntilExit`，防止大目录死锁；IPv6 主机去方括号后再传给 ssh
- 浏览远端是循环：`remoteJoin` 进入下一层、`remoteParent` 返回上一级，每一层都异步列目录再弹选择框

填充决策 `buildFillPlan` 是 Core 里的纯函数，与 UI 状态分离，由 `tests/main.swift` 覆盖串框场景；预设下拉用 `forceTrigger: .conn` 直接指定填哪个框。

## 7. 构建

[scripts/build.sh](../scripts/build.sh) 调用 `swiftc -O src/Core.swift src/main.swift`，输出到 `AI终端启动器.app/Contents/MacOS/`；每次构建都覆盖 `.app` 的 `Info.plist`；用 `pgrep/pkill -x` 精确匹配进程名重启；构建成功后把改名前的 `AI启动器菜单栏.app` 移入废纸篓。不签名。
